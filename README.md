# Ethereal Arena

網頁版雙人連線卡牌遊戲，TypeScript + Vite。畫面固定 16:9（以 1920×1080 為基準，會自動縮放）。

## 怎麼玩

**最簡單：** 直接用瀏覽器打開 `docs/index.html`（已經打包好的版本），雙擊就能玩。

**開發模式（改程式會即時更新）：**

```bash
npm install
npm run dev      # 開 http://localhost:5173
npm test         # 跑規則測試（含 2000 場隨機對打）
npm run build    # 重新打包到 docs/
```

大廳有四種模式：

| 模式 | 說明 |
|---|---|
| 建立房間 | 產生 6 位數房號，把房號給對手；對手加入後雙方各自選角 |
| 加入 | 輸入對方的房號 |
| 對戰電腦 | 你選隊伍，電腦隨機組隊、隨機出牌（測規則用） |
| 本機雙人 | 玩家一、玩家二輪流選角，同一台電腦輪流操作，畫面會跟著輪到的人翻轉 |

每種模式開打前都會進**選角畫面**：點角色加入隊伍（先點的在左邊，可以交換左右），右邊會顯示能力和完整牌組。連線時雙方各自選、看不到對方選誰。

### 連線方式

用 [PeerJS](https://peerjs.com/) 做端對端（P2P）連線：房主的瀏覽器負責跑遊戲規則，對手只送操作過去，所以**不需要自己架伺服器**。
配對時會用到 PeerJS 免費的公開配對伺服器。少數網路環境（例如某些手機網路）可能連不上，之後如果常發生，可以再加 TURN 伺服器或改成自架伺服器。

## 換上圖片

圖片放在 `public/assets/`，打包時會複製到 `docs/assets/`，沒放圖時會顯示佔位圖。開遊戲時會先預載所有圖片（有進度條），之後畫面和動畫都不會閃。
圖片格式是 WebP：生圖 AI 的原圖（PNG）用 `python scripts/optimize_images.py` 轉換，會縮成實際需要的大小（31 張圖約 2.6 MB）。
每個角色有一套統一規格的圖：立繪 `chars/`、卡圖 `cards/`、卡背 `backs/`（詳見提示詞檔的「卡背」；卡面由遊戲畫，不用底框圖）。
檔名和 AI 生圖提示詞都在 [`圖片提示詞.md`](./圖片提示詞.md)。

## 程式結構

詳細的架構、慣例、新增角色的步驟都在 [`AGENTS.md`](./AGENTS.md)（給一起協作的 AI 和人看）。簡單來說：

```
src/engine/   遊戲規則（純邏輯，跟畫面完全分開）
  chars/      每個角色一個檔；新角色在 chars/index.ts 登記
src/net/      本機、電腦、PeerJS 連線
src/ui/       畫面：render（畫）、anim（動畫）、input（操作）、popups、lobby
src/styles/   樣式，依畫面區塊分檔
src/config.ts 預設隊伍等設定
test/         規則測試、每個角色的測試、隨機對打壓力測試
```

## 規則實作備註

規則依照討論結果實作，下面這些是規則沒寫到、我先自己決定的地方，要改跟我說：

- 卡牌上的「打擊」傷害 = 使用者的 AT（薩凡娜是 1）
- 「-X TP」類效果（週轉、武裝千金）對瀕死單位也有效，可以直接把瀕死單位處決
- 重創的 -3 HP 是直傷，不吃負傷 +1
- 被救治的角色當回合不能行動，TP 維持瀕死時剩下的數值
- 被棄置的牌先 +1 財富，再結算它的「(棄置時)」效果，所以那 1 點財富可以拿來發動同一張牌的收買
- 雙方都用兩隻薩凡娜時，任一隻棄牌，兩隻都會 +1 財富
- 恕不退款（沒收買）：TP 照扣、重創照樣觸發，只是受傷不會 +1
- [洗牌]＝能力或卡牌效果把棄牌區洗回牌組後，再抽 1 張（專案擁有者確認）；武裝千金的我方全體洗牌是兩隻各抽 1 張，[瀕死]的角色只洗不抽；牌組抽完自動洗回不算[洗牌]

### 葛蘭妮

- 「我方棄牌」包含隊友棄的牌，所以葛蘭妮可以吞掉薩凡娜的牌；吞噬後抽 1 張的是葛蘭妮
- 吞噬的牌用掉（能力 4）或消化（能力 5）後，進的是**葛蘭妮的**棄牌區，之後會被洗進葛蘭妮的牌組
- 葛蘭妮用到別的角色的牌時，那張牌的專屬機制（例如薩凡娜的收買）因為沒有財富而不會發動
- 盤中餐、食肉的「吞噬 1 張牌」可以從我方任一角色的手牌選（先選角色、再選牌）
- 覓食的「本回合已棄過牌」只要我方任一角色這回合棄過牌就算
- 消化時把牌放進棄牌區不算「棄牌」（不會觸發暴食本能、財富）
- 吞噬的牌雙方都看得到
- 飲血回復的量 = 這次打擊對 HP 造成的傷害（打瀕死單位時是 0）

### 薩維爾

- [直擊]＝造成傷害、但**不減少對方 TP**（所以也不會打出[負傷]）；對[瀕死]單位仍會照常扣 TP，否則薩維爾永遠無法[處決]對手
- [直傷]（通緝令、餘燼的額外傷害）直接扣 HP，不吃[負傷]增傷和減傷，不會觸發 TP 相關規則；臨時 HP 也算 HP，會先被扣（專案擁有者確認）
- [主動攻擊]花 0 AP、改消耗 1 [焰能]；[焰能] 層數＝本回合還能主動攻擊幾次（上限 6 層），回合結束清空
- 沒有[焰能]時完全不能主動攻擊，要靠瞬焰、裝填先累積
- [連擊] 計數：每一次[打擊]都算 1 次（主動攻擊、卡片打擊、多段打擊的每一段都算）；打出卡片本身不算
- [連擊 3、4、5] 是「該次打擊結束後」給下一次攻擊 +1 AT，不可疊加；[連擊 6] 是「第 6 次打擊」那一次傷害 ×2（火輪擊的固定傷害也一樣 ×2）
- 瞬焰、裝填、通緝令的[連擊 X] 判斷，用的是「打出這張牌當下已經攻擊過幾次」
- 速拔的「下回合 -1 AT」直接改對方 AT，並記在對方身上，於薩維爾**下一個自己回合開始**時恢復；薩維爾若在這之前死亡就不會恢復
- 火神的通緝令只能指定敵方單位；標記在該單位身上，薩維爾回合結束時清掉
- 火神的通緝令（[連擊 0]）與薩達莉亞的餘燼的 +AP 可以超過 AP 上限
- 通緝令、餘燼的額外[直傷]不算一次攻擊，不會推進[連擊]
- 為了讓「每回合多次主動攻擊、且改用專屬資源付費」能在角色檔完成，核心新增通用 hook：`attackLimit`、`attackApCost`、`canAttack`、`onAttack`、`strikeOpts`、`onAttackHit`，以及 `strikeOnce/strike` 的 `direct`（直擊）、`power`（指定傷害）選項；核心沒有出現任何角色 id 判斷

### 拉尼斯

- [墬淵]：永久、不可疊加，最大 TP -1；目前的 TP 也會一起降到新上限，之後回合開始回滿、[瀕死]回滿、[負傷]判斷都用新的上限
- [洗牌]照共用詞條的定義：只有「能力／卡牌效果造成的洗牌」才算，牌組抽完自動洗回不算、也不會觸發能力 1
- 能力 1 的「AT 1 的[打擊]」是固定 1 點傷害＋-1 TP，不是拉尼斯的 AT 8；每回合最多 3 次，自己的回合開始時歸零
- 能力 1 只要**我方任一角色**[洗牌]都會觸發（和葛蘭妮的「我方棄牌」一樣）
- 能力 2：她所有「指定 1 名敵方單位」都只能選[墬淵]單位，也不受 SP 限制；場上沒有[墬淵]敵人時，普攻與需要指定敵人的牌都不能用（效果直接不發動）
- 能力 3：敵方單位進入[重創]就給[墬淵]，包含被她的效果打成[重創]；同一單位不疊加
- 能力 4：自己的回合結束時自動詢問，可選 0～3 張；手牌[移除]至棄牌區後，再從牌組**最上面**[移除]同樣數量至棄牌區（專案擁有者確認：移除＝丟到棄牌區）。都不算棄牌，不觸發棄牌相關的被動和(棄置時)
- 「移除 N 張牌至棄牌區」＝從牌組最上面拿 N 張進棄牌區：不算抽牌、不算棄牌、不觸發[洗牌]；牌組不夠就只移除剩下的
- 卡牌上「抽出此牌時」改成共用的「(抽出時)」寫法（`drawText`，和(棄置時)同一套），在抽到的當下就結算（含開局抽牌）；之後才打出去時不會再檢查棄牌區
- 正規化（專案管理）：「墬淵」是專案擁有者刻意用的字，保留；記事的錯字（不詳→不祥）修正；卡面文字統一成「N 點[直傷]」「≥」等寫法；瀆神海域的文字照實作改寫成「下一個陷入[重創]的單位額外受到 3 點[直傷]」；「移除 N 張至棄牌區」「移出牌局」改成共用詞條
- 瀆神海域：任一單位（雙方都算）陷入[重創]時額外受 3 點[直傷]，結算一次後效果就結束；順序是先扣[重創]本身的 -3，再扣這 3
- 黑漩、瀆神海域的「自身[洗牌]」照共用詞條：棄牌區洗回牌組後抽 1 張，也會觸發能力 1 的掃場
- 血叉的「上回合有[重創]」＝該單位自己上一個回合開始時是否處於[重創]
- 深淵巨口的「已損失生命一半」以最大 HP 計算、無條件進位；「指定的單位是[瀕死]單位」＝使用時就已經[瀕死]（專案擁有者確認），被這張牌打進[瀕死]不算；處決後回復自身 10 HP；這張牌用完直接移出牌局
- 能力 2 讓拉尼斯在敵方沒有[墬淵]單位時無法普攻、指定敵人的效果落空：這是設計（專案擁有者確認），她靠[洗牌]掃場造成傷害、靠隊友把敵人打進[重創]
- 為了這些機制，核心新增通用欄位／函式：`tpMaxDown`（永久最大 TP 減少，`g.effTpMax` 讀）、`removed`（移出牌局的牌）、`g.mill`／`g.removeHandCards`／`g.removeDeckTop`；通用 hook：`enemyTargets`（改用別的指定規則）、`onAllyShuffle`、`onUnitCritical`、`onOwnTurnEnd`；卡牌欄位：`onDrawCard`、`removeAfterPlay`；還有 `registerStatus`（掛在單位身上的共用狀態，畫面自動顯示徽章）。核心沒有出現任何角色 id 判斷

### 米雅

- [聖環]的「自身場上只能有一個」＝同一名單位只能有一個、不疊加；我方場上可以同時有多名[聖環]單位
- [聖環]「受到治療時回復 1 HP」直接加在該次治療量上（治療 3 → 回 4），不會多出一次治療事件；同一張牌對同一個單位只算一次治療（例如渙散祈禱對[聖環]單位是 1＋2＝3，再加 1，共 4）（專案管理正規化）
- [聖環]「自身回合結束回復 1 HP」在該單位擁有者的回合結束時結算，狀態在單位身上、不受米雅是否存活影響；這次回復不套用聖環自己的治療加成，但會觸發米雅的能力 3
- [聖環]「回合開始後解除」＝該單位擁有者的下一個回合開始時解除；永久[聖環]不會解除
- 能力 1：米雅的[救治]不限次數，也不佔用、不消耗一局一次的救治額度（隊友之後仍然可以救治米雅）
- 能力 2【聖旨】花費 2 AP，只能選「還沒有[聖環]」的我方單位；我方都已經有[聖環]時不能使用
- 能力 3：每回合（我方回合）第一次**實際**回復 HP 時抽 1 張，滿血不算；[聖環]的回合結束回復也算；每回合只抽一次，自己的回合開始時歸零
- 能力 4：只看隊友（另一個單位）有沒有[聖環]（永久也算），有就 SP -1，SP 可以到 -1
- 聖雅嘆息的「上回合有[負傷]」＝該單位自己上一個回合開始、TP 回滿之前的狀態（核心新增 `woundedPrev`，和[重創]的 `criticalPrev` 同一個時機記錄）
- 告罪：-2 AT 直接改目標的 AT，記成目標身上的[告罪]狀態（畫面有徽章），在**目標自己的回合結束時**加回去＝撐到米雅的下一個回合；米雅中途陣亡也會照樣恢復（專案管理正規化，原本米雅死掉就不會恢復）；AT 最低到 0，實際扣多少就記多少
- 沒興趣的「直到下個自身回合」用核心既有的 `dmgReduce`（各單位自己回合開始時歸零）
- 麻煩死了的臨時 TP 用核心的 `tTp`（扣 TP 時先扣臨時 TP）；角色數值列會顯示「臨時 TP +N」
- 不公之恩寵：(1) 只能選我方單位；已經有臨時[聖環]的會升級成永久；「永久 +1 TP」＝最大 TP +1，目前 TP 也 +1。(2) 只在有[瀕死]隊友時出現，救治免費（不用付 HP／AP），和一般救治一樣以「TP × 2」的 HP 回歸（核心 `g.reviveUnit`），也不算、不消耗一局一次的救治，之後再回復 5 HP。(3) 我方全體 10 HP。使用次數記在米雅身上，第 2 次使用後[移出牌局]
- 數值沒給的 SP 先設 0（能力 4 會讓它變成 -1）；AT 0、主動攻擊花 1 AP（打擊 0 點傷害，只是耗 AP）
- 為了這些機制，核心新增通用機制：`StatusDef.healBonus`（治療加成）、`StatusDef.onTurnStart`／`onTurnEnd`（掛在單位身上的狀態，在該單位擁有者的回合開始／結束時結算）、通用 hook `onAllyHeal`（我方單位實際回復 HP）與 `spDelta`（SP 加減）、`CharDef.rescueUnlimited`（不佔用一局一次的救治）、`removeAfterPlay` 可以寫成函式（依使用次數決定何時移出牌局）、`g.heal` 的 `raw`（不套用治療加成）、`g.rescueAllowed`、`Unit.woundedPrev`；核心沒有出現任何角色 id 判斷
